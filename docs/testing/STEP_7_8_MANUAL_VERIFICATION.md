## Fixes discovered by verification

- Normalize bill-list `COUNT` to a JSON number, matching the frontend pagination contract. MySQL's BIGINT string configuration previously returned a string count.
- Normalize SQL occupancy/enabled flags before branching. For a single-flat query, MySQL can return a calculated false flag as the string `"0"`; its JavaScript truthiness previously allowed an occupied-only charge for a vacant flat. Regression checks require single-flat and batch previews to agree and forbid generation for an excluded selection.

These changes are in `src/billing/queries.ts` and `src/billing/planning.ts`. Expanded coverage is in `tests/billing.integration.ts` and `tests/payments.integration.ts`. The allocation-failure trigger and connection flag are confined to the disposable integration schema; production migrations and payment writing SQL are unchanged.
