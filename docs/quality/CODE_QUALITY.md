The diagnostic override is not a committed suppression or Sonar analysis. Measured changes: CSV validate 52 to 9 (new focused methods maximum 12), report filter validation 30 to 7, error response callback 24 to 5 (classifier 12), and security header middleware 18 to 10. Maximum remaining application complexity is 26. Backend formatter/lint/typecheck, 37 unit tests/build and validation of 14 migration files passed. The final fresh-MySQL integration suite passed all 125 tests, including the helper-layout changes. No coverage percentage or cognitive-complexity/Sonar result is invented.

New regressions verify safe error classification/logs and accurate retry windows, read-origin restrictions, measured CSV statement reuse, fresh validation after data changes, inclusive occupancy boundaries and distinct occupancy types. Existing integration tests verify failed import rollback, tenant isolation, matching-reference identity reuse, similar-person nonmerge, financial failure injection/concurrency and immutable history.

## Performance review

The repeated-flat validation regression measures MySQL session `Com_stmt_execute`: three identical rows require exactly two lookup SELECTs (building + flat), with duplicate errors preserved on every row. Each validation gets a new cache; preview cache never survives revalidate/confirm. This is a statement-count regression, not a throughput benchmark.

Financial writes retain society and bill locks, canonical idempotency keys/hashes, bounded allocations and transactions. Billing generation has bounded per-bill/item writes; it cannot be converted to parallel writes without proving lock ordering/atomicity. Identity loading has a fixed set of queries, not one query per membership. Dashboards execute a fixed set of aggregate queries. Report SQL uses correlated ledger subqueries for totals/status: tenant/payment/bill indexes exist, but large ledgers require production-scale EXPLAIN and latency measurements before rewriting them. Deep OFFSET pages and substring searches can scan many rows even though response sizes are bounded. Exports pre-count/reject above 5000 rows and only materialize the bounded result.

No speculative cache, queue service, ORM, new database index/migration or broad financial refactor was introduced. Existing direct row-based DTOs follow mysql2 typed-row conventions; this review does not claim every internal DTO has been redesigned.
