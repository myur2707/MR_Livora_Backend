## Cross-cutting controls reviewed

- SQL values use mysql2 parameterized execution. Dynamic identifiers come from fixed resource tables, report sources/column policies, validated sort enums and validated migration/grant identifiers. Request fields are never copied into SQL identifiers. Strict Zod objects reject protected/unknown fields, invalid path IDs, oversized pages and unsupported query parameters.
- MySQL shared-schema isolation uses composite tenant foreign keys/unique constraints in addition to application scoping. Runtime and migration accounts are separate; runtime cannot grant roles, run DDL, rewrite completed money or modify/delete audit logs. Append-only triggers guard bills, allocations, refunds, receipts, audit logs and complaint history. No cascade deletion of completed financial/audit records. Runtime access to global identity is required for account linking, and is not a substitute for tenant validation.
- Money uses DECIMAL(12,2), database decimal strings and BigInt minor units; no authoritative JS floating-point totals. Billing snapshots do not change with future configuration. Payments/allocations/commands/receipt/audit commit atomically; corrections/refunds/reversals append evidence. Tenant serialization and database uniqueness protect concurrent commands; conflicts require safe retry, not silent overwrites.
- Argon2id reviewed work factors, random hashed reset/invitation tokens, HttpOnly/SameSite cookies, Secure/__Host cookies in production, safe request limits and rate controls remain intact. Production rejects insecure origin/HTTP, remote MySQL needs verified TLS, and proxy trust is an explicit single IP. API responses are no-store with safe errors and correlation-only operational logs.
- `.env.example` has placeholders. Local secrets, database state, build/test artifacts and portable tools are ignored. No frontend secrets/auth tokens in environment files or localStorage; only theme preference is persisted. Both Git histories and the nonignored working source are scanned locally with redaction.
- Upload support is CSV text only: authorized preview, strict headers/content parsing, UTF-8/replacement/NUL checks, 256 KiB/500-row/record-size limits, preview hashes and confirmation revalidation. Staging PII is minimized on confirmation/cancel/expiry. Binary attachments and XLSX are absent, so a malware scanner is not falsely claimed. Downloads are bounded formula-safe CSV and backend-authorized printable receipt data.
- Angular renders text through interpolation; no unsafe HTML injection/bypass APIs were found. PWA has one hashed static group, no runtime URL patterns/data groups; authenticated APIs/financial/private URLs bypass service-worker caching. Browser tests inspect actual Cache Storage/offline behavior.

## Step 12 checklist follow-up

The additional malformed-identifier probe exposed a low-severity validation availability issue: the shared unsigned identifier schema called `BigInt` even after a format failure, returning a generic 500 for SQL-like text. Piping format validation into the bounds refinement prevents throwing conversion and preserves the safe 400 contract. No injected query executed or internal error detail was exposed. A regression covers invalid strings/types and both valid unsigned bounds. Future schemas must validate inputs before potentially throwing conversions.

Production-mode error/log, SQL-injection search and protected-field probes were added. The requested checklist, audit-row inspection, final results and deployment limits are recorded in [STEP_12_MANUAL_VERIFICATION.md](../testing/STEP_12_MANUAL_VERIFICATION.md).
